# ADR 0002 — Живой workdir через SSHFS

**Статус — принято для ЧП2.**

Windows-клиент запускает SFTP-сервер на loopback и открывает обратный SSH-туннель в sandbox manager. Менеджер монтирует SFTP через SSHFS в выделенный каталог под `/run`, затем передаёт его контейнеру через bind mount. Контейнер агента работает с `/work` стандартными файловыми операциями при выключенной сети.

## Альтернативы

- **WebDAV/rclone** тоже позволяет держать клиентский порт закрытым через туннель. Потребовалась бы отдельная проверка режима VFS, задержек записи и замены файла с уже существующим именем.
- **NFS поверх WireGuard** даёт стандартную сетевую ФС на Linux. Для выбранного Windows-клиента усложняются экспорт папки, настройка UID и управление сетью.

## Компромиссы

Отключены кэши содержимого и атрибутов SSHFS для воспроизводимой проверки внешних изменений. Это повышает стоимость обхода дерева и чтения мелких файлов. Замена выполняется через SFTP `posix-rename` в исходном каталоге. Служебное состояние хранится отдельно. SFTP отфильтровывает `.git`, симлинки, hardlink и junction, проверяет выход за границы и режим доступа. Монтирование `ro` также защищено на стороне сандбокса.

Чтобы propagation заработал, дерево монтирования на Linux должно быть shared. На стенде Windows ↔ Ubuntu WSL2 это подтверждено для `/run`. Для изолированного CI подготовлен отдельный shared mountpoint. После закрытия сессии на Linux остаётся метаданный журнал. Рабочие файлы по-прежнему находятся у клиента.
