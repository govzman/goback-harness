# ADR 0001 — Runtime, транспорт и сессия

**Статус — принято для ЧП2.**

## Harness

Выбран Python-цикл с ограничением шагов и метаданными операций. Его можно прочитать целиком и заменить прокси либо сам сервис harness для сравнения пары. Рассматривались LangGraph с управляемым графом переходов и готовый агентный harness. Основная логика GoBack помещается в линейный цикл с четырьмя инструментами и операцией отмены. Подключение готового агента усложнило бы сквозную передачу версий и ID правок.

## Сандбокс и сеть

На сессию создаётся отдельный Docker-контейнер. Рабочий код выполняется с UID 65532, без capabilities, с read-only root и `no-new-privileges`. Ограничения Docker задают CPU, память и число процессов. Временный диск ограничивается `tmpfs`, а клиентский SFTP-сервер отдельно ограничивает суммарную запись. Сеть сандбокса выключена. Прокси модели остаётся в управляющей части.

Доверенный sandbox manager получает Docker socket и `SYS_ADMIN` для FUSE. Эти полномочия требуют высокого доверия к менеджеру и хосту. Сокет и устройство FUSE недоступны контейнеру агента. Оценивали rootless Docker и gVisor. Оба усложняют доступ к FUSE и настройку монтирования.

## Протоколы

Клиент использует HTTP для команд, SSE для упорядоченного потока и обратный SSH-туннель для данных папки. Рассматривали WebSocket для всего трафика. HTTP и SSE проще диагностировать отдельно, а SSH даёт стандартное шифрование для файлового канала. На локальном стенде управление работает по loopback. На внешнем адресе нужен TLS для HTTP и безопасной передачи SSH host key и клиентского токена.

Менеджер принимает запросы harness по HTTP внутри Compose и выдаёт NDJSON для операций. Альтернативой был gRPC. JSON-схема и поток достаточны для двух Python-сервисов.

## Сессии

Сессия связывает один mount, одну историю и один активный запуск. Разрешено до восьми сессий, у каждой отдельный контейнер, рабочая папка и ключи SFTP. Параллельный доступ к одной физической папке из нескольких сессий приводит к внешним изменениям, которые обнаруживаются при чтении и перед записью. Журнал операций существует в памяти. Журнал метаданных переживает перезапуск для диагностики. Оборванный SSE может продолжиться по курсору. При потере файлового канала клиент открывает новую сессию, а менеджер очищает старую после таймаута.
