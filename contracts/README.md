# Протоколы v0

Схемы описывают отдельные тела запросов и события в `$defs`. Версия задаётся путём `/v0` и полем `v` в ответах и событиях.

## Клиент и gateway

Запросы выполняются с `Authorization: Bearer <client-token>`. Идентификаторы сессий привязаны к клиентскому токену.

- `GET /v0/auth` проверяет токен.
- `POST /v0/sessions` принимает `prepare` со стороны клиента. В ответе `prepared` есть данные для SSH-туннеля.
- После открытия туннеля клиент вызывает `POST /v0/sessions/{id}/mount`.
- `POST /v0/sessions/{id}/messages` принимает `message`. Повтор с тем же ID и текстом возвращает тот же ID запуска.
- `GET /v0/sessions/{id}/events?after=N` выдаёт SSE с событиями `event`, начиная с `N + 1`. Клиент сохраняет последний полученный `seq` и восстанавливается от этой позиции.
- `POST /v0/sessions/{id}/edits/{edit_id}/undo` принимает `undo`. При неудачной отмене ответ и событие `undo_conflict` или `undo_failed` содержат известные факты об операции. Если ответ содержит `run_id`, по нему можно отследить пояснение агента в потоке SSE. Повтор с тем же ID возвращает сохранённый исход.
- `POST /v0/sessions/{id}/cancel` останавливает текущий запуск. `DELETE /v0/sessions/{id}` освобождает ресурсы.

## Harness и sandbox manager

Gateway вызывает `POST /v0/sessions` и `POST /v0/sessions/{id}/mount` для создания окружения. Harness передаёт `request` в `POST /v0/sessions/{id}/exec`. Сервис отвечает NDJSON с `accepted` и одним завершающим `result` с тем же ID. Код завершения и ограниченные stdout/stderr передаются в `result`.

- Результаты завершённых операций запоминаются в пределах сессии по ID. Повтор операции использует тот же ID.
- `command_error` содержит код выхода команды. Ошибка передаётся модели и оставляет ей возможность выбрать следующий шаг.
- `timeout` приводит к завершению контейнера. Для следующей операции менеджер может создать новый контейнер при доступном workdir.
- `workdir_disconnected` означает потерю связи с клиентской папкой. Пользователь может открыть новую сессию и заново открыть папку.
- `sandbox_error` означает сбой контейнера или менеджера. Харнес передаёт исход в контекст модели. Для `transport_error` исход вызова может быть неизвестен, поэтому перед повтором записи нужно сверить состояние файла. Автоматического повтора команд для этих исходов нет.
- `POST /v0/sessions/{id}/cancel` принимает ID запуска и удаляет контейнер с его процессами. Для следующего запуска контейнер создаётся снова. `GET /v0/sessions/{id}/collect` возвращает количество сохранённых результатов. `DELETE /v0/sessions/{id}` закрывает туннель и освобождает mount.
