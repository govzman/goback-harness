# GoBack Harness

Среда исполнения coding-агента для задания A курса ITMO × DeepPavlov. Клиент делится выбранной папкой через SSHFS, сандбокс агента видит её как `/work`. GoBack отменяет конкретную правку поля JSON и сохраняет последующие изменения в соседних полях. При конкурирующей правке того же поля GoBack сообщает о конфликте. [ТЗ проекта](https://github.com/deeppavlov/agentic-course-itmo/blob/main/projects/A-agent-runtime.md)

## Сервер

На Linux нужны Docker Engine, Compose, `/dev/fuse` и монтирование `/run` с распространением shared. Запускай из корня клона.

```sh
docker compose up --build
docker compose down -v
```

Первая команда работает в отдельном терминале до окончания демо. В WSL2 это удерживает дистрибутив запущенным. Если сборка контейнеров в WSL2 не достаёт до репозиториев пакетов, используй `docker compose -f docker-compose.yml -f compose.wsl.yml up --build`. Оверлей меняет сеть на этапе сборки.

Сервер по умолчанию слушает loopback, использует токен `goback-local-demo` и фиксированные ответы модели для демо. Настройки можно переопределить в локальном `.env` из `.env.example`. Для стенда на отдельной машине укажи в `GOBACK_BIND` адрес в доверенной сети и выбери собственный `CLIENT_TOKENS`. При работе вне доверенной сети защити канал клиента TLS.

## Клиент и демо

Клиенту нужен Python 3.12. Установи зависимости в своём виртуальном окружении.

```sh
python -m pip install -r client/requirements.lock
```

Создай отдельную папку и положи в неё `config.json` с содержимым `{"port": 8080, "workers": 2}`. CLI запустит сценарий, сделает тестовую правку со стороны клиента и проверит результат.

```sh
python client/cli.py run --folder ./demo-workdir --mode rw --message "Change the port in config.json to 9090" --demo neighbor
```

Должно получиться `{"port": 8080, "workers": 3}`. Для второго прогона восстанови исходный JSON и укажи `--demo conflict`. На этот раз пользовательская правка `port: 7070` должна сохраниться.

## Подключение модели

- Для API-ключа установи `LLM_MODE=api` и `LLM_API_KEY` в локальном `.env`. Модель и effort задаются `LLM_MODEL` и `LLM_REASONING_EFFORT`. Ключ получает только LLM proxy.
- Для входа через подписку запусти `python3 services/llm-proxy/chatgpt_login.py` на сервере или в локальной WSL2 с Python и пакетом `cryptography`. Подтверди вход в браузере на том же ПК и выбери модель из выведенного каталога. Запусти Compose с `-f docker-compose.yml -f compose.chatgpt.yml`. Эта интеграция пока требует проверки на живой модели. [Sign in with ChatGPT](https://developers.openai.com/siwc/token-sharing-open-source)

## Устройство

```text
клиент ── HTTP и события ──► gateway ──► harness ──► LLM proxy
папка ── SFTP через SSH ─────► sandbox manager ─────► контейнер /work
                                       ▲
                                       └──── вызовы инструментов от harness
```

Отмена доступна в рамках открытой сессии для правок существующих скалярных полей JSON через специальный инструмент. Учитываются значения полей и версия файла при сохранении. Пользователь должен сохранить свою правку перед отменой. Редактор может записать файл в узком интервале между проверкой и атомарной заменой, поскольку не участвует в общем блокировании. Перезапуск сервисов завершает сессии.
