# Инфраструктурные проверки

`make test-infra` запускает `test_runtime.py` через обычный клиентский API. Для проверок нужен запущенный стек в режиме `fixture`. В CI используется отдельный тестовый секрет, который передаётся прокси модели и проверяется на отсутствие в сандбоксе.

## Текущее покрытие

- Подключение с неверным токеном и режим `ro`.
- Двусторонняя запись в workdir, отмена с сохранением соседнего поля, конфликт при правке того же поля.
- Повтор запроса отмены по ID, порядок событий и чтение с последнего SSE-курсора.
- Изоляция `.git`, ссылок на Linux, Docker socket, серверных секретов и сети. Сценарий также проверяет UID, capabilities и `no-new-privileges`.
- Лимиты CPU, RAM и PID по cgroup, read-only root, заполнение временного диска и таймаут команды.
- Остановка фонового процесса при cancel и выполнение следующего запуска в той же сессии.
- Потеря SSH-туннеля и сигнал о недоступном workdir. Отдельный шаг GitHub Actions проверяет очистку контейнеров после тестов.

Для полного покрытия ТЗ ещё нужны валидация сообщений по обеим схемам, прямой повтор sandbox-exec и проверка финального результата на уровне протокола, таймауты остальных операций, отдельная попытка выхода через `..`, исчерпание PID-лимита, падение харнесса посреди команды, параллельные сессии и тесты разрешённых сетевых профилей. [Сверка с ТЗ](../../docs/requirements.md)

Замеры ФС и сандбокса и сравнение способов отмены запускаются командами из корневого README. [Команды и результаты](../../README.md#проверки-и-воспроизводимость)
